# אבטחה: תקציר בעברית

תקציר של [security.md](security.md). המסמך המלא באנגלית מחייב.

## מה קיים
- בידוד בין עסקים: RLS מאולץ בכל טבלה של עסק, וכל תפקיד הוא משתמש מסד נתונים נפרד עם הרשאות מינימליות.
- אימות HMAC לכל webhook; תהליך פרוס לא עולה בלי סוד אמיתי.
- סודות ב-Secret Manager; Cloud SQL בכתובת פרטית בלבד; רק שירות ה-web ציבורי.

## חשיפת הקונסולה
- לקונסולה אין עדיין כניסת צוות. ההחלטה (T3): הקונסולה רצה כתהליך נפרד (`main.js console`) וכשירות Cloud Run נפרד עם ingress פנימי בלבד, בלי הרשאת `allUsers`.
- שירות ה-web הציבורי לא רושם את נתיבי הקונסולה בכלל (מחזיר 404).
- מקומית הקונסולה עונה רק ל-loopback; בפריסה השער הוא הרשת וה-IAM. אין גישה מהמחשב האישי (גם לא דרך `gcloud run services proxy`, שעובר דרך החזית הציבורית). הגישה: מכונה בתוך ה-VPC (דרך IAP SSH) שקוראת לכתובת הפנימית עם identity token; המכונה עוד לא ב-Terraform, ועד אז הקונסולה בפריסה לא נגישה.
- זה שער רשת, לא הזדהות: מי שיש לו `run.invoker` יכול לבצע כל פעולה, כולל ביטול עסק.

## חובות טכניים (לפי סדר חשיבות)
1. D1: אין כניסה לקונסולה ואין זהות למבצע הפעולה.
2. D2: נתיב `cancel` מוחק עסק בלי הרשאה אמיתית.
3. D3: CSRF ו-DNS rebinding על הקונסולה המקומית.
4. D4: השדה `by` נלקח מגוף הבקשה.
5. D5: הרשאות ברמת עמודה למשתמש `console` (שלא יוכל להעביר שורה בין עסקים דרך `business_id`).
6. D6: `CREATE ROLE ... IF NOT EXISTS` לא קובע מאפייני תפקיד; צריך `ALTER ROLE ... NOINHERIT NOCREATEROLE NOBYPASSRLS`.
7. D7: מספר החיבורים בכל ה-pools מול `max_connections` של Cloud SQL.
8. D8: `trustProxy` כבוי; אסור להסתמך על כתובת IP.
9. D9: הקונסולה רצה עם חשבון השירות של web וטוענת את כל הסיסמאות.
10. D10: `set_config` הוא סיכון מקובל, נתפס רק בבדיקת קוד המקור.
11. D11: הודעות נכנסות בזיכרון התהליך (T2).
12. D12: אין הגבלת קצב ונפח גוף בקשה.
13. D13: מדיה בזיכרון עד WP-41.
14. D14: לוגים עלולים להכיל תוכן לקוח (T14).

כל חוב הוא חבילת עבודה בתוכנית המימוש (WP-80 עד WP-87, ו-T11, T2, WP-41, WP-47 למכוסים).
