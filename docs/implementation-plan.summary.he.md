# תוכנית מימוש: עיקרי הדברים

התוכנית מחלקת את שלב 1 לחבילות עבודה, וכל חבילה נבנית בסשן נפרד של סוכן קוד. סשן מנהל אחד מריץ לולאה: בוחר חבילות מוכנות, פותח להן סשנים, בודק את התוצאה, מביא לאדם את נקודות האישור, וחוזר על כך עד שהכול גמור.

- **מסלולים:** ליבה (סשן אחד בכל פעם), מקבילי (עד שלושה סשנים, כל אחד ב-worktree משלו) ואנושי (החלטות ואישורים שרק אדם נותן).
- **מיגרציות (7.11.2026):** לכל היותר PR פתוח אחד עם מיגרציה בכל רגע. המנהל מחזיק "אסימון מיגרציה" ונותן אותו בבריף לסשן אחד. הסשן כותב קודם את שינוי הסכמה ואת הבדיקות, ומריץ את `npm run db:generate` בצעד האחרון, מיד אחרי מיזוג `origin/dev`. ה-CI מריץ `npm run db:check` (`drizzle-kit check`) ונכשל אם שרשרת ה-snapshots נשברה.
- **נקודות אישור אנושיות:** אישור החוזים, מפרט שלושת הסגנונות והפונטים, אוסף הדוגמאות בעברית, בדיקת מיגרציות ו-RLS, בדיקות האישור והפרסום שהאדם כותב או מאשר, נוסחי השיחה והתבניות, פרומפטים ללקוחות, וסודות ומדיה.
- **שלבים:** תשתית (גבולות מודולים, CI, רתמת בדיקות קצה לקצה, סימולטורים), אבן דרך 1 (מנוע העיצוב ואוסף הדוגמאות), ליבת המערכת (מסד נתונים, שכבת מודלים, הודעות, מנוע זרימה), תהליכי המוצר (הצטרפות, עדכון שבועי, טיוטות, אישור, פרסום, מקרי כשל), ושוליים (קונסולה, ספקים אמיתיים, חיוב, פריסה, וסביבת ניסוי מקומית).
- **סביבת ניסוי מקומית (WP-45):** ממשק שרץ רק במחשב המקומי: צ'אט בסגנון וואטסאפ שבו האדם משחק את בעל העסק מול הסימולטורים, פיד מדומה של אינסטגרם ופייסבוק שמראה מה פורסם, ופאנל מצב. כך אפשר לבדוק כל תהליך לפני החיבור לוואטסאפ ולרשתות האמיתיים.
- **סביבת dev מדומה (WP-51, דחוף):** dev רץ מקצה לקצה בלי חשבונות ספקים: הסימולטורים עם מצב משותף ב-Postgres, ו-sandbox פנימי עם צ'אט, פיד מדומה ודף תשלום מדומה.
- **הסשן המנהל:** לא כותב קוד מוצר. הוא מריץ את הבדיקות על כל ענף, מפעיל סוכן סוקר נפרד, מציג לאדם את בדיקות הקצה לקצה והדוחות, וממזג רק אחרי אישור.
- **מצב עבודה (מ-2.11.2026):** נקודות האישור כבר לא עוצרות את העבודה, חוץ מתשלום כסף אמיתי ופריסה לענן. כל השאר נרשם בתור הבדיקה האנושית (human-review-queue.md) והאדם בודק בקצב שלו. סשן סוקר נפרד בודק, מאשר וממזג כל PR ב-squash. בדיקות האישור והפרסום נכתבות על ידי סשן נפרד שלא מממש, וממוזגות לפני המימוש. חבילות שצריכות חשבונות ספקים נשארות חסומות עד שהאדם מספק אותם.
- **פערים בחוזים שנמצאו בבניית הסימולטורים:** לבקשה למודל אין שם משימה, לספק התשלום אין דרך לגלות את מזהה המנוי אחרי תשלום, ואין שגיאה מוגדרת לשליחה מחוץ לחלון 24 השעות. כל חבילה שנוגעת בהם מציעה את שינוי החוזה במסמכים לפני המימוש.
- **פערים בתיעוד:** סשן שנתקל בהחלטה שחסרה במסמכים עוצר ומדווח. ההחלטה נכנסת למסמכים קודם, ורק אחר כך נכתב קוד.
- **מצב:** החוזים אושרו ב-2.11.2026. מפרט הסגנונות ואוסף הדוגמאות זמניים, ומספיקים כדי להתחיל את מנוע העיצוב.
- **התחלה מומלצת:** קודם גבולות מודולים ו-CI. אחר כך, במקביל: מסלול הליבה (רתמת הבדיקות ומסד הנתונים), והמסלול המקבילי (סימולטורים, אוסף הדוגמאות הזמני ומנוע העיצוב).
- **החלטות האדם מ-3.11.2026:** הסגנונות מאושרים בינתיים ויעברו מחקר ושדרוג (WP-14); אוסף הדוגמאות הזמני הוא אוסף העבודה; גישת כותב הבדיקות מאושרת; הנוסחים מספיקים לדמו. נוספו חבילות להקשחת מסד הנתונים (WP-24) ולניקוי הערות הסקירה (WP-15).
- **מסלול הליבה (מ-3.11.2026):** האדם מתיר כמה סשנים של ליבה במקביל כשהם נוגעים בקבצים נפרדים.
- **חבילות חדשות (מסקירת התור, 4.11.2026), כולן לביצוע בהמשך:** יומן ביקורת שמור לכל אירוע במנוע הזרימה, שהתקבל או נדחה (WP-46); ניטור: לוגים מובנים בלי תוכן לקוחות, מדדים ומעקב, לוחות ניטור והתראות ב-Terraform, ומדריך תגובה (WP-47 עד WP-50); שלב ליטוש של נוסחים וגיוון בהודעות (WP-60); ובעתיד: בעל העסק בוחר שעה מדויקת, כמה פוסטים ביום, והמלצות AI לשעות הטובות (WP-70 עד WP-72).
- **עדכון אחרי סגירת השבוע (WP-31):** נחשב לעדכון של השבוע הבא. ההחלטה ממתינה לאדם בתור הסקירה.
- **ענפים:** כל PR של חבילת עבודה נפתח מול `dev` ומתמזג אליו; קידום ל-`stage` ול-`main` (prod) הוא PR נפרד.
- **חובות אבטחה (מתוך security.md):** הגנת CSRF ו-DNS rebinding בקונסולה (WP-80); `trustProxy` לפי קפיצה אחת של Cloud Run (WP-81); כניסת צוות לקונסולה ותיעוד מי פעל (WP-82); אישור בהקלדת שם העסק לפני ביטול (WP-83); הגדרות וחשבון שירות נפרדים לכל תהליך (WP-84); הגבלת נפח וקצב בקשות (WP-85); בחינה מחדש של סיכון `set_config` (WP-86); גודל מאגרי החיבורים מול מגבלת Cloud SQL (WP-87). חלק מהחובות כבר מכוסים: T11, T2, WP-41, WP-47.
- **שלב 7: הסוכנת (5.11.2026, העדיפות העליונה של האדם):** WP-89 חוזי הסוכנת בקוד (קודם לכול); WP-90 מנוע הסוכנת ומסגרת הכלים, כולל הקונסולה והמיגרציה; WP-91 רתמת בדיקות עם סוכנת מתוסרטת (בלי מודל אמיתי); WP-92 אונבורדינג; WP-93 עדכון שבועי; WP-94 טיוטות עם עריכות תמונה וקרוסלה (ומריץ הגלריה של WP-13 חייב להציג תגים); WP-95 התג בעיצוב; WP-96 הערכה ידנית אופציונלית מול Gemini; WP-97 בחינה מחדש של המודל וההיסטוריה אם Flash Lite חלש מדי. לכל חבילה רשימת קבצים משלה: חוזים רק ב-WP-89, רישום כלים בקבצים נפרדים לכל סוכן, פרומפט במיגרציה נפרדת לכל סוכן. העיצוב ב-agent.md.
- **WP-89 כולל גם** את מיגרציה 0017 (משימות הסוכנת ב-enum, שורות Flash Lite ופרומפטים זמניים); כל חבילת סוכנת מוסיפה את הפרומפט האמיתי כגרסה 2.
- **שלב 8: לפני הסביבה האמיתית הראשונה (6.11.2026):** WP-98 מאחד את כל המיגרציות למיגרציית בסיס אחת, כדי שסביבה חדשה תעלה מסקריפט נקי אחד. מותר רק כל עוד אין בשום סביבה נתוני לקוחות אמיתיים; אחרי זה מיגרציות רק מתווספות ולעולם לא מאוחדות שוב. מחכה למיזוג ה-PRs הפתוחים שמוסיפים מיגרציות (H4).
- **WP-98 כולל גם (7.11.2026):** ניקוי הסכמה בזמן האיחוד: מספר טלפון אחד בהודעה במקום שניים ו-`payload` מצומצם; עדכון שבועי מפנה להודעות המקור במקום להעתיק את הטקסט; טבלאות קישור למדיה במקום מערכי מזהים; enum של Postgres הופך ל-text עם CHECK. לפני שמסמנים את dev כמעודכן, משווים לסכמה החיה שלו.
- **שלב 9: אחסון שגדל (7.11.2026):** כלל האדם: לא מוחקים לצורך מקום שום דבר שנעשה עבור לקוח או על ידו; נתונים ישנים עוברים לאחסון זול ואיטי יותר שעדיין אפשר לקרוא. WP-99 מעביר את תוכן קריאות המודל וצעדי הסוכנת ל-Cloud Storage (דחוס), עם מעבר הדרגתי ל-Nearline, Coldline ו-Archive; מחזור החיים לעולם לא מוחק, והמחיקה היחידה היא מחיקת עסק מבוטל לפי הכלל הקיים (WP-43). WP-100 מחלק לפי חודש רק טבלאות שאף טבלה אחרת לא מפנה אליהן (`model_run`, `workflow_event`, `console_action`); `message` ו-`agent_turn` לא מחולקות, כי אישור מפנה להודעה שלו כראיה. חודשים ישנים מיוצאים ל-Parquet שאפשר לשאול דרך BigQuery, ורק אחרי בדיקה יורדים מ-Postgres; מחיקת עסק מבוטל עוברת גם לקבצים המאורכבים, חוץ מיומן הביקורת שנשמר. כלל המחיקה 30 יום אחרי ביטול ב-PRD לא משתנה עד שהאדם יחליט. WP-87 הושלם (#92).
