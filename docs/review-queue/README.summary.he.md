# פריטי תור הבדיקה: עיקרי הדברים

מ-7.11.2026 כל פריט שהאדם בודק הוא קובץ משלו בתיקייה הזו, אחד לכל PR. הפריטים הישנים נשארים עם המספרים שלהם ב-human-review-queue.md, והטבלה שם לא גדלה יותר.

- **למה קובץ לכל PR:** כשכל PR הוסיף שורה לאותה טבלה, כל שני PRs פתוחים התנגשו. קובץ בשם מספר ה-PR ייחודי מרגע פתיחת ה-PR.
- **מי כותב:** ה-PR שנוגע באזור שדורש בדיקה אנושית (H1 עד H8, בדיקת קצה לקצה חדשה או שהשתנתה, או שינוי ב-CI ובכללי המיזוג) מוסיף את `docs/review-queue/pr-<N>.md`. הסוקר בודק אותו מול השינוי. כשהאדם מחליט, משתנה רק הקובץ של הפריט.
- **מבנה:** כותרת קדמית עם `added`, `pr`, `gates` ו-`status`, כותרת, הטקסט באנגלית, ואחריו סעיף `## עברית` קצר. הסעיף בעברית באותו קובץ מחליף קובץ סיכום נפרד.
- **בדיקה:** `npm run lint:review-queue` בודק כל קובץ, ו-CI מריץ אותו.
- **רשימה:** `npm run review-queue` מדפיס את כל הפריטים הפתוחים משני המקומות בטבלה אחת; `--all` מדפיס הכול, ו-`--json` מדפיס JSON ללוח העבודה של המנהל.
