# Onboarding keeps brand images sent early; request_photo only in brand_assets

The fix for onboarding never finishing on dev (2026-11-09). What to check:

- **Customer media (H8).** `src/modules/workflow/onboarding.ts`: owner images sent before `brand_assets` are kept as asset ids in `conversation_state.open_question.photoAssetIds`, the same place onboarding already keeps business photos. On `PROFILE_FIELDS_COMPLETE`, `carryEarlyAssets` makes the first one the logo when none is set. Check that the logo-then-photos rule is what you want when an owner's first early image is a product photo rather than a logo; it is the existing rule from technical-design.md.
- **Agent guidance (H7).** The onboarding agent's done-rule text (`src/modules/agent/agents/onboarding.ts`), which goes into the model's context, now says not to ask for photos during the profile questions, that saved assets count, and to `record_decline` instead of asking again. `prompt_template` is unchanged.
- **Tool rules.** The onboarding agent gets `request_photo` only in `brand_assets` (`AgentDefinition.toolsIn`), and at most two requests per purpose (`photo_request_limit`).
- **E2E.** `test/e2e/onboarding-early-assets.e2e.test.ts` replays the dev sequence.
