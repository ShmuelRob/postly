# Workflow changes: CI path filter, reviewer auto-merge, lanes

The workflow proposal's items 1, 2, 3 (docs), 5, 9, 11 and 12, which the human approved on 2026-11-07. What to check:

- **The CI path filter** (`.github/workflows/ci.yml`, `scripts/lane.ts`). A docs-only PR skips the test jobs, and `check` still passes. Check the docs-only list in [implementation-plan.md](../implementation-plan.md#change-size-lanes): only `docs/**/*.md` and top-level `*.md`, never the contract docs, the gate docs, or any doc whose path a `*.test.ts` names. `check` fails if the tests were skipped for any other reason. Inside Deploy every job always runs.
- **The merge rule** ([operating mode](../implementation-plan.md#operating-mode)). A reviewer approves by posting a `review` commit status on the exact SHA and turning on auto-merge pinned to it. Any session can post that status, just as any session can merge today. Repository settings were not changed. The manager turns on auto-merge, then requires `review`, after this PR merges.
- **The light local gate** (`npm run check:local`). Sessions no longer run the full `npm run check` locally, and CI is the gate. A session that adds or changes an e2e test still runs that test locally and shows the report.
- **The review-queue format** ([README.md](README.md)). An item's Hebrew summary lives in its own file, not in a separate companion.
