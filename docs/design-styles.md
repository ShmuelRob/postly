# Postly Design Styles

Status: provisional (2026-11-02; researched rules added 2026-11-03 by WP-14, still queued under H2). These are example styles so the design engine can be built and judged now. The human replaces them with the final style spec, and the provisional example set with the real Hebrew example set, before milestone 1 closes.

Each style is a set of strict rules applied by code to fixed HTML templates. Nothing here is generated by a model. The `TemplateRenderer` contract in [contracts.md](contracts.md) is the interface; this document fixes what it draws.

## Output

| Item | Rule |
| --- | --- |
| Canvas | 1080 x 1350 (4:5) for every network and every carousel slide. The renderer still returns one file set per network, so sizes can diverge later without a contract change |
| File | JPEG, quality 90, sRGB, no metadata |
| Carousel | 2 to 10 slides; slide 1 is the cover with the overlay text, the rest are photos with the frame and logo only |
| Direction | `rtl` for Hebrew and Arabic, `ltr` for English and Russian; a mix follows the first language in `languages` |
| Fonts | Self-hosted from the repository under the SIL Open Font License; no network access during rendering |
| Overlay text | At most 2 lines and 40 characters. Text is shrunk down to the style's minimum size; if it still does not fit, rendering fails and the caller shortens it |
| Safe area | 64 px on every side; text and logo never leave it. This also keeps them inside the 3:4 profile-grid crop of a 4:5 post (1012 x 1350, 34 px off each side) |
| Photo | Cover-cropped to the canvas, centered on the `image_review` crop when one exists |

## Rules for every style

Researched on 2026-11-03 (WP-14) and checked for every style, including pale and dark brand colors, in `src/modules/design/styles/rules.test.ts`. Sources follow the table.

| Rule | Value | Why |
| --- | --- | --- |
| One message | The overlay text is one short message: at most 2 lines and 40 characters (see Output). Details go in the caption | A feed post gets about a second on a phone; Meta favors little text on the image |
| Text-to-image ratio | The overlay text box covers at most 20% of the canvas | Meta retired the hard 20% text limit in 2021 but still states that images with under 20% text tend to perform better |
| Mobile size | The overlay text is never smaller than 48 px on the 1080 px canvas, about 17 pt on a phone 390 pt wide | A post shows at roughly a third of its pixel width on a phone; smaller display text stops reading at a glance |
| Text panel | Overlay text never sits directly on the photo; it sits on a solid panel of the style (band, card) | A photo's colors are unknown, so only a solid panel makes the contrast below provable in code |
| Text contrast | Overlay text and the name-as-logo reach 4.5:1 against their panel (WCAG 1.4.3 AA); text color is recomputed when a brand color would break it | Holds at the smallest size, so no large-text exception is relied on |
| Graphic contrast | Graphic elements (bars, rules, stripes, bands) reach 3:1 against what they sit on (WCAG 1.4.11). On a panel, a brand color that falls short is mixed toward black (light panel) or white (dark panel) in 5% steps until it passes, so its hue survives. Over the photo, the element gets an offset edge in the style's shadow color, or white when the shadow is below 3:1 against the element | Closes the open gap: a pale brand color such as `#E8B4C8` made the Clean bar and the Dynamic stripes faint |
| Hebrew typography | `lang` and `dir` on the page; no letter-spacing on overlay text; line height at least 1.1 times the font size; explicit line breaks (`\n`) kept in every style (`white-space: pre-line`, set by the engine for every overlay) | W3C Hebrew layout requirements treat letter-spacing as emphasis, not a default; tighter Hebrew display lines collide |
| Carousel cover | Slide 1 carries the only overlay text; later slides are photos with the frame and logo | The cover is the hook that decides the swipe; repeated text adds no new message |
| Logo | At most 160 x 160 (about 15% of the width), never upscaled, inside the safe area | The brand stays visible without competing with the message |

Sources:

- WCAG 2.1, [Understanding 1.4.11 Non-text Contrast](https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast) and technique [G207](https://www.w3.org/WAI/WCAG21/Techniques/general/G207): 3:1 for graphical objects against adjacent colors. WCAG 2.1 1.4.3: 4.5:1 for text.
- W3C, [Hebrew Layout Requirements](https://www.w3.org/International/hlreq/) and the [Hebrew gap analysis](https://www.w3.org/TR/2024/DNOTE-hebr-gap-20240920): letter-spacing in Hebrew is an emphasis device.
- Meta's statement that images with under 20% text generally perform better, after the hard limit was removed in 2021, as reported by [Xanthos Digital](https://www.e-xanthos.co.uk/facebook-officially-removes-20-text-limit-in-ad-images) and [Bronco](https://www.bronco.co.uk/our-ideas/?p=6427). Meta's own current help page was not checked directly; worth confirming.
- Instagram size guides on the 4:5 feed size and the 3:4 profile-grid crop: [Inro](https://www.inro.social/blog/instagram-post-size), [SocialBu](https://socialbu.com/blog/instagram-post-aspect-ratio). Vendor blogs; they disagree on which edges the grid trims, and the 64 px safe area covers both readings.
- Claude skills: `frontend-design` and `artifact-design` cover web UI, not social posts, and add nothing beyond the hierarchy and contrast rules above. The community `hebrew-rtl-best-practices` skill (skills-il) also says not to track Hebrew.

## Brand colors and logo

- With brand colors, the first color replaces the style's accent color and the second replaces its secondary color. Text color is recomputed so contrast stays at least 4.5:1 (WCAG AA), and graphic elements follow the 3:1 rule above.
- Without a logo, the business name is set as text in the style's headline font at the logo position.
- The logo is scaled to fit a 160 x 160 box and never upscaled beyond its native size.

## Styles

### Clean

Bold typography, plenty of white space, few elements.

| Rule | Value |
| --- | --- |
| Fonts | Heebo 800 for the overlay text, Heebo 400 for secondary text |
| Palette | Background `#FFFFFF`, text `#111111`, accent `#2F6BFF` |
| Layout | Photo fills the top 70%; a white band below holds the overlay text, start-aligned |
| Overlay size | 72 px, minimum 52 px |
| Frame | None |
| Accent | A 12 px accent bar on the band's start edge, at 3:1 against the white band |
| Logo | Band, end side, vertically centered; on carousel photo slides, the bottom end corner. Without a logo, the name sits on a background-colored chip |
| Unused for now | The second brand color and Heebo 400; there is no secondary text yet |

### Warm

Earth tones and textures.

| Rule | Value |
| --- | --- |
| Fonts | Frank Ruhl Libre 700 for the overlay text, Assistant 400 for secondary text |
| Palette | Background `#F3E9DC`, text `#3B2A1E`, accent `#B5683C`, secondary `#7A8450` |
| Layout | Photo inset with the frame; the overlay text sits on a paper-texture card overlapping the bottom of the photo |
| Overlay size | 64 px, minimum 48 px |
| Frame | 32 px background-colored margin with 24 px rounded photo corners |
| Card | `#FBF6EE`, 16 px corner radius; a short two-part rule in the accent and secondary colors, each at 3:1 against the card; the secondary color also tints the card edge |
| Texture | A subtle paper grain over the background, generated in code (SVG noise), so no image asset is needed |
| Logo | Top corner on the start side, on a 232 px background-colored circle |

### Dynamic

Bold graphic elements and a sense of movement.

| Rule | Value |
| --- | --- |
| Fonts | Rubik 900 for the overlay text, Rubik 500 for secondary text |
| Palette | Text `#FFFFFF`, accent `#FF3D5A`, secondary `#FFC83D`, shadow `#14141F` |
| Layout | Full-bleed photo; the overlay text sits on an accent-colored band rotated by -4 degrees across the lower third |
| Overlay size | 80 px, minimum 56 px |
| Frame | None |
| Graphic elements | Two diagonal stripes in the secondary color in the top start corner (the logo takes the top end), with an 8 px offset edge; the band has a 16 px offset edge. Edges use the shadow color, or white when it is below 3:1 against the element |
| Unused for now | Rubik 500; there is no secondary text yet |
| Logo | Top corner on the end side, white |

## Provisional example set

Until the human supplies the real set, the example set holds six fictional Hebrew businesses: a florist, a bakery, a hair salon, a falafel stand, a pet shop, and a yoga studio. Each has a complete `BusinessProfile`, one weekly update in Hebrew, and 3 placeholder photos generated in code (gradients with simple shapes), so no third-party images enter the repository. Every entry is marked `provisional: true`.

Each entry also states its expected outcomes, which the runner and later prompt evaluation compare against (decided 2026-11-02, queued for the human under H3):

- **Facts:** the `fact_extraction` output the weekly update should produce (`id`, `type`, `value`, `sourceQuote`), where every `sourceQuote` appears verbatim in the update.
- **Missing details:** what the agent should ask the owner about, empty when nothing is missing.
- **Overlay texts:** the cover texts to render, each within the overlay text limit above.

The file layout is described in `fixtures/example-set/README.md`.
